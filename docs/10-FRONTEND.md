# 12. 프론트엔드 설계

프론트엔드는 저장소의 `frontend/` 에 둔다. 네 층으로 나눈다. 화면에 그리는 편집기, 편집기의 변화를 연산으로 바꾸는 어댑터, 서버와 맞추는 협업 클라이언트, 연결을 관리하는 전송 층이다. 이 중 어댑터가 프로젝트 전체에서 가장 불확실한 부분이라 가장 먼저 검증한다.

## 12.1 층 구성

| 층 | 위치 | 책임 |
| --- | --- | --- |
| 편집기 | `src/editor/` | Tiptap 스키마(블록 10종, 서식), 키 입력, 슬래시 메뉴, 드래그 핸들, 남의 커서 그리기 |
| 어댑터 | `src/collab/adapter/` | 편집기에서 일어난 변화를 연산 묶음으로, 받은 연산을 편집기 변경으로 바꾼다 |
| 협업 클라이언트 | `src/collab/client/` | 확정 문서, inflight, buffer를 관리하는 상태 기계. 되돌리기 목록. 오프라인 저장 |
| OT 코어 | `src/collab/ot/` | `ot-core` 의 TypeScript 구현. 적용, 변환, 합성, 역연산 |
| 전송 | `src/collab/transport/` | 티켓 발급, WebSocket 연결, 재접속(지수 백오프 1초부터 최대 30초, 무작위 지연 포함), 핑 |
| 상태 저장소 | `src/stores/` | Pinia: 인증, 워크스페이스와 트리, 알림, 댓글 |
| 화면 | `src/views/`, `src/components/` | 3장의 화면 9개 |

협업 클라이언트와 OT 코어는 Vue를 모르는 순수 TypeScript로 짠다. 브라우저 없이 Vitest에서 돌리기 위해서다.

## 12.2 편집기 어댑터

Tiptap(ProseMirror)은 문서 전체를 하나의 위치 체계로 다루고, 이 설계의 연산은 블록 ID와 블록 안 위치를 쓴다. 두 체계를 잇는 방법은 이렇다.

| 방향 | 방법 |
| --- | --- |
| 편집기에서 연산으로 | Enter, Backspace, Tab, 드래그 이동, 종류 변경처럼 의도가 분명한 동작은 키맵과 명령을 가로채 `split`, `merge`, `moveBlock`, `setProps` 를 직접 만든다. 그 밖의 변화(타이핑, 붙여넣기, 한글 조합)는 트랜잭션 전후 문서를 블록 ID로 비교해, 바뀐 블록의 글자 차이를 `text` 로, 새 블록을 `insertBlock` 으로, 사라진 블록을 `deleteBlock` 으로 만든다 |
| 연산에서 편집기로 | 연산이 건드린 블록만 찾아 ProseMirror 트랜잭션으로 바꾼다. 텍스트 연산은 그 블록의 시작 위치를 더해 위치 기반 변경으로 넣는다. 내 커서는 ProseMirror가 변경에 맞춰 옮겨 준다 |

주의할 점이 두 가지 있다.

- 한글은 조합 중에 글자가 계속 바뀐다(ㄱ, 가, 각). 조합이 끝날 때까지 연산을 buffer에서 합성해 하나로 보내고, 조합 중인 블록에 남의 연산이 오면 조합이 끝난 뒤 반영한다. 조합 중에 DOM을 건드리면 입력이 깨진다.
- 남의 연산을 반영한 트랜잭션은 "원격" 표시를 달아 어댑터가 다시 연산으로 만들지 않게 한다. 편집기 자체의 되돌리기 기록은 끄고 6.7의 되돌리기를 쓴다.

## 12.3 협업 클라이언트 상태 기계

| 상태 | 들고 있는 것 | 내가 편집하면 | 서버 ack가 오면 | 남의 연산이 오면 |
| --- | --- | --- | --- | --- |
| 동기화됨 | 없음 | 바로 보내고 "확인 대기"로 | 해당 없음 | 그대로 반영 |
| 확인 대기 | inflight | buffer에 담고 "확인 대기 + 버퍼"로 | "동기화됨"으로 | inflight를 변환하고, 받은 연산도 변환해 반영 |
| 확인 대기 + 버퍼 | inflight, buffer | buffer에 합성 | buffer를 보내고 "확인 대기"로 | inflight와 buffer를 차례로 변환하고, 받은 연산도 변환해 반영 |
| 오프라인 | inflight(불확실), buffer | buffer에 합성하고 IndexedDB에 저장 | 해당 없음 | 해당 없음 |

"받은 연산을 반영"하는 방법은 화면 문서를 고치는 것이 아니라 다시 계산하는 것이다. 받은 연산을 확정 문서에 적용하고, inflight와 buffer를 변환한 뒤, 확정 문서에 둘을 차례로 적용해 화면 문서를 새로 만든다. 편집기에는 이전 화면 문서와 달라진 블록만 반영한다.

예외가 세 가지 있다. 규칙은 `ot-core` 의 `ClientSession` 에 구현되어 있고 TypeScript 구현도 같은 규칙을 따른다.

- nack를 받으면 inflight와 그 위에 쌓은 buffer를 버리고 화면을 확정 문서로 되돌린다. 사용자에게는 "다른 사람의 편집과 겹쳐 방금 입력이 취소되었습니다"라고 알린다.
- inflight를 변환하다 충돌이 나면 서버도 같은 충돌로 거부할 것이 확실하므로, nack를 기다리지 않고 바로 화면을 되돌린다.
- 변환은 됐지만 지금 확정 문서에 적용할 수 없는 inflight(예: 두 사람이 블록을 서로의 아래로 옮김)는 화면에서만 빼 두고 서버의 판정을 기다린다. 뒤이어 오는 연산 때문에 서버에서는 적용될 수 있어서, 여기서 버리면 서버와 어긋난다.

## 12.4 오프라인 저장

IndexedDB에 문서별로 세 가지를 둔다.

| 저장 항목 | 내용 | 쓰는 시점 |
| --- | --- | --- |
| 확정 문서 | 마지막으로 확인한 리비전과 문서 내용 | ack나 남의 연산을 받은 뒤 2초 모아서 |
| 대기 묶음 | `clientId`, `clientSeq`, 연산, 기준 리비전 | 묶음이 생기거나 바뀔 때마다 |
| 클라이언트 정보 | `clientId`, 다음 `clientSeq` | 묶음을 만들 때마다 |

- `clientId` 는 탭마다 다르다. 같은 사람이 탭 두 개를 열면 서로 다른 참여자로 동작한다.
- 오프라인 상태로 탭을 닫으면 대기 묶음이 남는다. 같은 문서를 다시 열 때 주인 없는 대기 묶음을 발견하면 그 `clientId` 를 이어받아 재접속 절차(7.5)를 밟는다. 두 탭이 동시에 이어받지 않도록 Web Locks API로 잠근다.
- 로그아웃하면 이 저장소를 비운다. 공용 PC에 문서가 남지 않게 하기 위해서다.

## 12.6 첫 구현에서 정한 것

편집기 어댑터의 첫 구현(문단 블록만)에서 정하거나 문서와 다르게 한 것이다.

| 항목 | 정한 것 | 이유 |
| --- | --- | --- |
| 편집기 경로 | `/w/:workspaceId/p/:pageId`. 예전 주소 `/p/:pageId` 는 페이지의 워크스페이스를 찾아 옮긴다 | 공유받은 주소에는 워크스페이스가 없을 수 있다 (D-22) |
| 첫 화면 | 페이지를 만들 수 있는(OWNER, MEMBER) 워크스페이스가 있으면 그리로 간다. 없으면 게스트로 있는 워크스페이스 목록과 워크스페이스 만들기 | GUEST 는 최상위에 페이지를 만들 수 없다 |
| 사이드바 | 워크스페이스 고르기, 새 페이지, 페이지 트리(펼칠 때 한 단계씩 읽는다), 페이지마다 하위 페이지 만들기(EDIT 이상), 멤버 | 다른 사람의 트리 변경은 아직 바로 받지 않는다(W-5, D-23). 내가 만든 페이지와 고친 제목은 바로 보인다 |
| 공유 창 | 편집기 머리의 "공유"(FULL 만). 이메일로 주기, 등급 바꾸기, 회수, 물려받은 권한 보기, 제한 켜고 끄기 | S-3. 바꾸면 상대 편집기에 1초 안에 적용된다(S-5) |
| 멤버 화면 | OWNER 가 가입한 사용자를 이메일로 넣고, 역할을 바꾸고, 내보낸다 | 초대 메일(W-1 invites)이 생기기 전의 임시 경로 (D-22) |
| 편집기 문서 모양 | 제목(루트 블록) 하나와, 루트 아래 보이는 블록을 깊이 우선으로 늘어놓은 블록들. 블록 노드는 중첩하지 않고 `depth` 속성으로 들여쓰기를 그린다. 노드마다 `blockId` 속성 | 중첩 노드보다 커서 이동과 위치 변환이 단순하다. 트리는 블록의 부모 ID 가 나타낸다. 편집기가 노드를 나눠도 ID 가 따라가지 않게 해서 ID 없는 노드를 새 블록으로 본다. 붙여넣은 HTML 의 ID 는 읽지 않는다 |
| 블록과 서식의 이름 | 편집기 노드 이름은 블록 종류와 같고 코드 블록만 `codeBlock`. 마크 이름은 서식 이름과 같다 | 편집기는 노드와 마크(인라인 코드 `code`)가 같은 이름을 쓸 수 없다 |
| 서식 바꾸기 | 전후 비교에서 글자는 같고 서식만 다른 범위는 `retain(n, 바뀐 서식)` 으로 만든다. 꺼진 서식은 null | 지우고 다시 넣으면 그 사이 다른 사람이 그 범위에 친 글자가 밀려난다 |
| 블록 종류와 속성 | 도구 막대, 마크다운 단축 입력, 할 일 체크는 편집기 노드만 바꾸고 전후 비교가 `setProps` 로 만든다. 저장하는 속성은 제목 단계(`level`), 할 일 체크(`checked`), 코드 언어(`language`) | 가로채는 키가 아니어도 같은 길로 연산이 된다 |
| 마크다운 단축 입력 | `# `, `## `, `### `, `- `, `1. `, `[] `, `> `, ```` ``` ````, `---`. Tiptap 기본 입력 규칙 대신 블록 ID 와 깊이를 지키는 규칙을 쓴다 | 기본 규칙은 노드 속성을 새로 만들어 블록 ID 를 잃는다 |
| Enter | 목록, 할 일, 토글은 같은 종류로 이어 가고 나머지는 문단. 빈 목록, 할 일, 토글, 인용, 콜아웃에서는 나누지 않고 문단으로 바꾼다. 자식이 펼쳐져 있으면 뒤쪽 블록이 첫 자식이 된다. 코드 블록 안에서는 줄을 바꾼다 | 다른 편집기와 같은 동작 |
| Backspace (블록 처음) | 문단이 아니면 먼저 문단으로 바꾼다. 위 줄이 구분선이면 구분선을 지운다. 합칠 블록에 자식이 있으면 먼저 바로 뒤 형제로 옮긴 뒤 합친다 | 6.6 의 "자식이 남은 블록은 합칠 수 없다" |
| Tab, Shift+Tab | Tab 은 앞 형제의 마지막 자식으로, Shift+Tab 은 부모의 다음 형제로 옮긴다. 내어쓸 때 뒤에 있던 형제는 이 블록의 자식으로 따라온다. 코드 블록 안의 Tab 은 공백 두 칸 | 화면 순서가 바뀌지 않는다 |
| 토글 접기 | 내 화면에만 적용하고 문서에 저장하지 않는다. 접힌 토글의 자식은 편집기 문서에 넣지 않는다 | 다른 사람의 화면을 바꾸지 않는다 |
| 블록 종류 고르기 | 슬래시 메뉴(E-6) 대신 도구 막대의 목록 | 슬래시 메뉴는 다음 작업 |
| 가로채는 키 | 문단의 Enter 는 `split`, 블록 처음의 Backspace 는 앞 문단으로 `merge`, 블록 끝의 Delete 는 다음 문단을 `merge`. 제목에서 Enter 는 본문 맨 앞에 빈 문단, 빈 첫 문단의 Backspace 는 그 문단을 지운다 | 루트 블록은 나누거나 합칠 수 없다 |
| 그 밖의 입력 | 트랜잭션 전후를 블록 ID 로 비교한다. 글자 차이는 앞뒤로 같은 부분을 남긴 `text` 하나, 사라진 블록은 `deleteBlock`, 새 노드는 `insertBlock` | 편집기는 한 트랜잭션에서 보통 한 곳만 바꾼다. 이모지 가운데에서는 자르지 않는다 |
| 원격 반영 | 블록 순서가 같으면 바뀐 글자 부분만 바꾸고, 블록이 생기거나 사라지면 문서 전체를 바꾸고 커서를 (블록 ID, 위치)로 되돌린다 | 앞쪽은 편집기가 커서를 옮겨 준다 |
| 한글 조합 | 조합이 시작되면 협업 클라이언트를 멈춘다. 받은 메시지는 쌓아 두고 보내지 않는다. 조합이 끝나면 쌓인 메시지를 처리하고 다시 그린다 | 받은 메시지를 바로 처리하면 화면 문서가 편집기 문서와 어긋나, 조합 중에 만든 연산의 위치가 틀어진다 |
| 재발급 409 | 잠시 뒤 한 번 더 시도한다 | 다른 탭이 방금 재발급했다 (9.1) |
| `rebase: false` | 대기 편집을 버리고 받은 문서부터 다시 시작한다 | 복사본 페이지로 보관하는 것(7.5)은 페이지 트리가 생기는 3단계에서 한다 |
| 순서 키가 같을 때 | 동시에 같은 자리에 넣어 앞뒤 블록의 키가 같으면 새 블록은 앞 블록 키 바로 뒤로 놓는다. 아주 드물게 뒤 블록 다음에 보일 수 있다 | 키가 같은 두 블록 사이에는 키를 만들 수 없다 |
| TypeScript | 5.9 | Vue 파일을 검사하는 `vue-tsc` 가 TypeScript 의 JS API 를 쓰는데, 네이티브 구현인 7.0 에는 그 API 가 없다 |
