# 16. 위험과 미정 사항

가장 큰 위험은 편집기 어댑터이고, 0단계 2주 안에 계속 갈지 대안으로 바꿀지 판단한다.

## 16.1 위험

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| ProseMirror의 변화를 연산으로 바꾸는 과정에서 놓치는 경우가 생김 (붙여넣기, 한글 조합, 여러 블록 삭제) | 화면과 서버 문서가 어긋난다 | 0단계에서 먼저 검증한다. 어댑터가 만든 연산을 확정 문서에 적용한 결과와 편집기 문서를 개발 모드에서 매번 비교한다. 다르면 바로 오류를 낸다 |
| split과 merge의 변환 규칙에 빠진 경우가 있음 | 특정 순서에서 문서가 갈라진다 | 속성 테스트와 수렴 시뮬레이션을 1단계 완료 기준으로 둔다. 통과 전에는 서버를 만들지 않는다 |
| 두 언어 구현이 미묘하게 다름 (문자열 길이, 정렬 순서, 숫자 처리) | 클라이언트만 어긋난다 | 적합성 벡터를 CI에서 매번 돌린다. 클라이언트가 주기적으로 문서 해시를 서버와 비교해 다르면 다시 받는다 |
| 거부율이 예상보다 높음 | 입력이 자주 취소되어 쓰기 불편하다 | 사유별 거부율을 재고, 가장 잦은 사유부터 변환 규칙으로 옮긴다 |
| 24주 안에 범위를 다 못 함 | 측정과 문서화가 빠진다 | 14.2의 순서로 줄인다. 측정 단계는 남긴다 |
| 4GB 서버에서 노드 2대와 DB가 메모리 부족 | 시연 중 종료 | 팬파라이브의 메모리 예산 방식(컨테이너별 상한, 측정 스크립트)을 가져온다 |

## 16.2 정해야 할 것

- [ ] 서비스 이름 (지금은 가칭 코페이지)
- [ ] 시작일. 정해지면 14장의 주차를 날짜로 바꾼다
- [ ] 이미지와 파일 업로드를 고도화에 넣을지
- [ ] 소셜 로그인(A-4)을 할지, 한다면 구글과 깃허브 중 어느 쪽인지
- [ ] 화면 디자인 시안 (키 컬러, 사이드바와 편집기 배치, 커서 12색)
- [ ] 링크 공유로 들어온 비로그인 방문자에게 편집까지 허용할지, 댓글까지만 허용할지
