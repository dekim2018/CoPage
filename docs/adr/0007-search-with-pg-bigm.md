# ADR 0007. 검색은 PostgreSQL과 pg_bigm으로 한다

- 상태: 확정
- 결정일: 2026-11-22
- 관련 문서: [08-FEATURES.md](../08-FEATURES.md)

## 고른 것

PostgreSQL + pg_bigm

## 버린 대안

Elasticsearch, OpenSearch

## 이유

- 4GB 서버에 검색 엔진을 띄울 메모리가 없다.
- 페이지 수만 건 규모에서는 DB 인덱스로 충분하다.
- 별도 저장소와의 동기화 문제도 생기지 않는다.

## 감수하는 것

- 형태소 분석이 없다.
- 관련도 순 정렬이 단순하다.

## 다시 검토할 조건

13장의 부하 측정과 장애 실험 결과가 이 결정의 전제와 다르게 나오면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.

## 덧붙임 (2026-11-25, D-47)

만들 때 pg_bigm 대신 pg_trgm 으로 시작했다. 08-FEATURES 10.5 에 적어 둔 대안이다. pg_bigm 은 PostgreSQL 공식 이미지에 없어 확장을 빌드한 이미지를 따로 관리해야 하고, 관리형 DB 에서 쓸 수 있는지도 확인해야 한다. pg_trgm 은 세 글자 단위라 두 글자 이하 검색어는 인덱스가 걸러 주지 못하고 워크스페이스의 페이지를 다 훑는다(결과는 맞다). "PostgreSQL 안에서 검색한다"는 이 결정의 핵심은 그대로이므로 상태는 바꾸지 않는다. 두 글자 검색이 느리다는 측정이 나오면 pg_bigm 이미지로 옮긴다.
