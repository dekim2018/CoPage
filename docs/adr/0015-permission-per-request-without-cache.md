# ADR 0015. 권한은 요청마다 재귀 CTE 로 계산하고 캐시하지 않으며, 바뀌면 열린 연결에 다시 적용한다

- 상태: 확정
- 결정일: 2026-11-24
- 관련 문서: [07-SECURITY.md](../07-SECURITY.md) 9.4, 9.5, [review/DECISIONS.md](../review/DECISIONS.md) D-02, D-11, D-17, D-19, D-20

## 고른 것

- 페이지 권한은 묻는 때마다 `permission` 모듈이 계산한다. 재귀 CTE 하나로 페이지부터 루트까지의 사슬(restricted, 휴지통 여부)과 사슬 위의 내 부여, 내 워크스페이스 역할을 함께 읽고, 규칙은 순수 함수(`PermissionRules`)로 적용한다.
- 권한 캐시는 두지 않는다.
- 권한이 바뀌면 커밋한 뒤 `PermissionChangeListener` 포트로 "영향받는 페이지와 사용자" 를 알린다. `collab` 이 그 페이지의 열린 세션에서 그 사용자의 연결만 다시 계산한다. 계산(저장소 읽기)은 세션 실행 흐름 밖에서, 적용은 실행 흐름 안에서 한다. 등급이 바뀌면 `role` 메시지, 잃으면 4003 이다.
- 권한은 설계 9.4 를 앞당겨 워크스페이스 모델로 한 번에 만든다.

## 버린 대안

- `perm:{pageId}:{userId}` 를 Redis 에 캐시하고 바뀌면 지운다.
- WebSocket 연결을 열 때 한 번만 검사한다.
- 문서마다 접근 목록 하나(`doc_access`)로 최소 공유만 먼저 한다.

## 이유

- 캐시를 지우는 시점을 잘못 잡으면 회수한 권한이 남는다. 트리 이동이나 restricted 변경은 하위 전체의 캐시를 지워야 해서 틀리기 쉽다.
- 계산은 티켓 발급, 페이지 조회, 목록, 공유 설정 같은 REST 요청에서만 한다. 편집마다 하지 않는다. 편집은 세션이 연결마다 들고 있는 등급으로 검사한다(9.5).
- 연결을 열 때만 검사하면 권한을 회수해도 열린 편집기에서 계속 고칠 수 있다(S-5).
- 실행 흐름에서 DB 를 읽으면 그 문서의 모든 편집이 그만큼 늦어진다.
- `doc_access` 로 시작하면 3단계에서 워크스페이스 모델로 다시 만들어야 한다.

## 감수하는 것

- 요청마다 재귀 질의 하나가 든다. 하위 목록은 부모의 사슬을 한 번 읽고 자식마다 한 칸을 붙여 계산해 자식 수만큼 다시 읽지 않는다.
- 알림은 프로세스 안에서만 간다. 노드가 여럿이면 다른 노드의 열린 연결에는 닿지 않는다(4단계에서 Redis pub/sub 으로 넓힌다).
- 등급이 내려간 뒤 도착한 묶음은 nack 로 버려진다(D-20).
- 다시 계산이 실패하면 아무것도 바꾸지 않는다. 다음 재접속 때 새 티켓이 바른 등급을 준다.

## 확인

`LiveRevocationTest` 가 노드 1대에서 내리기 9ms, 회수 16ms, 제한 16ms, 내보내기 9ms 안에 열린 연결에 적용되는 것을 확인했다(2026-11-24, 로컬 개발 기기).

## 다시 검토할 조건

부하 측정에서 권한 계산이 병목으로 보이면 캐시를 넣고 이 문서를 고친다. 다중 노드에서 알림 전달이 늦어 1초 목표를 넘으면 다시 본다.
