# ADR 0017. 거부되거나 버려진 편집은 블록 단위로 살리고, 못 살린 글은 보관함에 보인다

- 상태: 확정
- 결정일: 2026-11-24
- 관련 문서: [10-FRONTEND.md](../10-FRONTEND.md) 12.3, 12.6, [05-PROTOCOL.md](../05-PROTOCOL.md) 7.3, [review/DECISIONS.md](../review/DECISIONS.md) D-27, D-20

## 고른 것

서버가 묶음을 거부하거나(nack), 변환이 충돌하거나, `rebase: false` 를 받아 클라이언트가 편집을 버려야 할 때, 구조 편집(넣기, 나누기, 합치기, 옮기기, 지우기)이 섞이지 않은 블록의 글과 속성 편집만 떼어 지금 문서에 맞춰 새 묶음으로 다시 보낸다. 살리지 못한 편집에서 사용자가 친 글은 편집기 위 보관함에 "글 복사" 와 함께 보인다. nack 에 사유 분류 `code`(permission, input, empty, rejected)를 더하고, rejected 일 때만 다시 보낸다.

## 버린 대안

- 묶음과 그 위에 쌓인 입력을 통째로 버린다(예전 방식, ADR 0012 의 "되돌림").
- 구조 편집까지 다시 변환해 살린다.

## 이유

- 한 블록의 글과 속성 편집은 다른 블록의 편집과 위치가 얽히지 않는다. 그 블록에 구조 편집이 없으면 같은 블록의 남의 편집에 변환으로 위치만 맞추면 된다.
- 구조 편집은 거부된 바로 그 이유(충돌)일 가능성이 크다.
- 권한, 입력, 빈 묶음으로 거부된 것은 다시 보내도 거부된다. 권한 회수 뒤의 편집은 남지 않아야 한다(D-20).
- 상태 기계(`ClientSession`)의 동작은 Java 와 같아야 한다(적합성 벡터). 살리기는 그 바깥(`salvage.ts`, `collabClient.ts`)에서 해 두 구현의 규칙을 바꾸지 않는다.

## 감수하는 것

- 살려 다시 보낸 글이 그사이 바뀐 문맥에서 뜻이 달라질 수 있다. 위치는 변환으로 맞추므로 엉뚱한 블록에 가지는 않는다.
- 이미 한 번 살려 보낸 묶음이 다시 거부되면 되풀이하지 않고 보관함으로 보낸다.
- 복사본 페이지로 남기는 일(7.5)은 아직 하지 않는다.

## 관계

ADR 0012(일부 구조 충돌은 거부한다)를 바꾸지 않는다. 거부는 그대로이고, 거부된 뒤 사용자가 잃는 것을 줄인다.

## 다시 검토할 조건

보관함이 자주 보이거나, 살린 편집이 뜻을 바꾸는 사례가 보고되면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.
