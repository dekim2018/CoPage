# ADR 0005. ack 전에 DB에 커밋하고 묶음 커밋으로 처리량을 지킨다

- 상태: 확정
- 결정일: 2026-11-22
- 관련 문서: [06-DATA-MODEL.md](../06-DATA-MODEL.md)

## 고른 것

ack 전에 DB 커밋, 묶음 커밋

## 버린 대안

메모리에만 적용하고 나중에 모아서 저장

## 이유

- 나중에 저장하면 노드가 죽을 때 이미 남에게 보인 편집이 사라진다.
- 화면들이 서로 다른 문서를 보게 되고 복구할 방법이 없다.

## 감수하는 것

- ack가 DB 왕복 시간만큼 느리다.
- 내 화면은 낙관적으로 먼저 그리므로 체감은 없다.

## 다시 검토할 조건

13장의 부하 측정과 장애 실험 결과가 이 결정의 전제와 다르게 나오면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.

## 후속

- 2026-11-24: 커밋 경로의 DB 왕복을 묶음 수와 상관없이 한 번으로 줄였다. 연결별 순번 규칙과 INSERT 문 하나다([ADR 0016](./0016-per-connection-seq-and-single-insert.md), D-38). 이 결정의 "ack 가 DB 왕복 시간만큼 느리다" 가 왕복 한 번으로 정해졌다.
- 장애 실험에서 DB 에 200ms 를 더해도 남에게 보인 묶음은 모두 이미 저장되어 있었다(`DbLatencyTest`). 커밋이나 저장소 읽기가 실패하면 세션을 버린다(D-33).
