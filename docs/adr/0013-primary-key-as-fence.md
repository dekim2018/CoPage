# ADR 0013. 펜싱 토큰 없이 연산 로그의 기본 키를 펜스로 쓴다

- 상태: 확정
- 결정일: 2026-11-23
- 관련 문서: [03-ARCHITECTURE.md](../03-ARCHITECTURE.md) 5.3, [06-DATA-MODEL.md](../06-DATA-MODEL.md) 8.1, [review/DECISIONS.md](../review/DECISIONS.md) D-04

## 고른 것

`doc_ops` 의 기본 키 `(doc_id, rev)` 와 세션마다 빈틈없이 이어지는 리비전을 낙관적 동시성 검사로 쓴다. 다중 노드에서 Redis 리스는 "누가 세션을 들지" 를 정하는 데만 쓰고, 정합성은 DB 기본 키로 지킨다.

## 버린 대안

리스를 잡을 때 늘어나는 펜싱 토큰(세대 번호)을 받아 모든 쓰기에 싣고, 저장소가 더 작은 토큰의 쓰기를 거절한다.

## 이유

- 세션은 저장소의 마지막 리비전에서 시작해 1씩 늘려 쓴다. 리스가 만료된 줄 모르는 노드가 쓰는 리비전은 새 주인이 이미 썼거나 곧 쓸 리비전이다. 둘 중 늦게 쓴 쪽의 INSERT 가 기본 키에 걸려 실패한다. 실패한 노드는 세션을 버리고 연결을 4009 로 닫는다.
- 펜싱 토큰은 저장소가 토큰을 검사해야 효과가 있다. PostgreSQL 에서 그렇게 하려면 문서마다 토큰을 저장하고 쓰기마다 비교해야 한다. 기본 키가 이미 같은 일을 한다.
- 커밋은 묶음 여러 개를 INSERT 문 하나로 넣는다(ADR 0016). 문장이 원자적이라 일부만 들어가는 경우가 없다.

## 감수하는 것

- 늦게 쓴 노드는 커밋에서야 실패를 안다. 그 노드에 붙은 클라이언트는 그 사이 ack 를 받지 못하고, 재접속해 같은 순번으로 다시 보낸다.
- 리비전이 겹치지 않는 경우(새 주인이 아직 아무것도 쓰지 않았고 옛 노드가 먼저 씀)에는 옛 노드의 쓰기가 들어간다. 새 주인은 그 뒤 리비전에서 기본 키에 걸려 세션을 버리고 저장소에서 다시 연다. 문서는 갈라지지 않는다.
- 연산 로그에 시간 범위 파티션을 쓸 수 없다(ADR 0011).

## 다시 검토할 조건

다중 노드(로드맵 4단계)의 노드 일시 정지 실험에서 같은 리비전이 두 번 들어가거나, 세션 버리기가 잦아 사용자가 느끼면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다. 지금은 노드가 한 대라 이 경로를 실험하지 않았다.
