# 14. 개발 일정

전체 24주, 8단계다. 가장 불확실한 두 가지(편집기 어댑터, 변환 규칙)를 맨 앞에 두고, 둘 다 통과한 뒤에 서버와 부가 기능을 올린다. 시작일이 정해지면 주차를 날짜로 바꾼다.

## 14.1 단계별 산출물과 완료 기준

| 단계 | 주차 | 만드는 것 | 완료 기준 |
| --- | --- | --- | --- |
| 0. 검증 실험 | 1~2 | Tiptap 어댑터 시제품(문단 블록만), 텍스트 변환 초안, pg_bigm 호환 확인 | 브라우저 탭 2개가 메모리 서버를 거쳐 같은 문단을 동시에 고친다. 한글 조합이 깨지지 않는다 |
| 1. OT 코어 | 3~6 | 연산 7종의 적용, 변환, 합성, 역연산 (Java). TypeScript 구현. 적합성 벡터 | 속성 테스트와 수렴 시뮬레이션 100만 회 통과. 두 구현의 벡터 1만 건 일치 |
| 2. 협업 서버 | 7~10 | 문서 세션, WebSocket 규약, 연산 로그와 스냅샷, 프레즌스, 로그인과 토큰, 블록 10종 편집기 | 노드 1대에서 여러 명이 한 페이지를 편집하고, 서버를 재시작해도 내용이 남는다 |
| 3. 워크스페이스와 권한 | 11~13 | 워크스페이스, 페이지 트리, 권한 계산, 초대, 공유 링크, 연산 단위 인가 | 권한 표(9.4)의 모든 칸이 통합 테스트로 검증된다. 권한 회수가 1초 안에 열린 화면에 적용된다 |
| 4. 오프라인과 다중 노드 | 14~16 | IndexedDB 대기열, 재접속과 멱등 재전송, 소유 리스, 양도, 프록시 해시 | 노드 2대에서 장애 실험 7종(13.2)이 통과한다 |
| 5. 부가 기능 | 17~19 | 버전 기록과 복원, 댓글, 멘션과 알림, 검색, 되돌리기 | 2장의 P1 항목이 전부 동작한다 |
| 6. 측정과 개선 | 20~22 | `loadgen`, 부하 시나리오 5종, 병목 개선, 결과 문서 | 1.4의 성공 기준 표가 실측값으로 채워진다. 목표에 못 미친 항목은 원인과 함께 적는다 |
| 7. 배포와 정리 | 23~24 | AWS 배포, README, 시연 영상, 에러 모니터링 SDK 연결 자리 마련 | 공개 주소에서 테스트 계정 2개로 동시 편집을 확인할 수 있다 |

## 14.1.1 지금 상태 (2026-11-24)

단계 순서대로 가지 않은 것이 있다. 아키텍처 진단(2026-11-23, [review/DECISIONS.md](./review/DECISIONS.md))을 처리하면서 3단계의 권한(SEC-1)을 앞당겼고, 4단계와 6단계의 장애 실험과 부하 측정 일부를 노드 1대로 먼저 했다.

| 단계 | 상태 | 한 것 | 남은 것 |

## 14.2 일정이 밀릴 때 줄이는 순서

1. P2 항목 전부 (소셜 로그인, 즐겨찾기, 이름 붙인 버전)
2. 검색을 제목 검색으로 축소
3. 블록 종류를 10종에서 6종으로 축소 (토글, 콜아웃, 인용, 구분선 제외)
4. 댓글의 멘션과 알림

동시 편집, 오프라인 재접속, 다중 노드, 측정은 줄이지 않는다. 이 네 가지가 1.1에서 증명하려는 내용이기 때문이다.
