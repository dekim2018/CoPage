# 10. 부가 기능 설계

버전 기록, 댓글, 멘션, 검색은 모두 연산 로그 위에 얹는다. 별도의 동기화 장치를 만들지 않고 6장의 연산과 8장의 로그를 다시 쓴다.

이 장의 기능은 아직 만들지 않았다. 로드맵 5단계에서 만든다. 지금 있는 것은 그 바탕뿐이다. 연산 로그와 스냅샷(8장), 협업 서버가 허용하는 `comment`, `mention` 서식 이름(6.1), 서버가 `comment` 서식만 바꾸는 COMMENT 등급의 연산을 허용하는 규칙(9.5)이다.

## 10.1 버전 기록과 복원

만들었다(D-44). 설계와 다른 점: 자동 시점은 세션이 아니라 서버의 주기 작업(1분마다, 편집이 2분 조용하거나 마지막 버전에서 10분이 지난 문서)이 남긴다. 복원 묶음은 서버가 아니라 클라이언트가 계산해 보통 편집으로 보낸다(`restore.ts`). 그래서 문서를 맡은 노드가 어디든 같은 길로 가고, 내 되돌리기 목록에 들어가 Ctrl+Z 로 되돌릴 수 있다. 복원 버튼은 FULL 에게만 보인다. 서버가 복원을 따로 막지는 않는다(EDIT 이면 같은 편집을 손으로도 할 수 있다).

| 항목 | 설계 |
| --- | --- |
| 자동 시점 | 편집이 이어지는 동안 10분에 한 번, 그리고 마지막 편집자가 나갈 때 `doc_versions` 에 AUTO 행을 남긴다 |
| 목록 표시 | 시각, 그 구간에 편집한 사람들. 편집자는 `doc_ops` 를 리비전 구간으로 묶어 구한다 |
| 과거 시점 보기 | 그 리비전 이하의 가장 가까운 스냅샷을 읽고 남은 연산을 적용해 읽기 전용으로 보여 준다. 문서 세션을 거치지 않는다 |
| 복원 | 로그를 되감지 않는다. 현재 문서를 과거 시점 내용으로 바꾸는 연산 묶음을 계산해 보통 편집처럼 세션에 제출한다 |

복원을 하나의 편집으로 다루면 세 가지가 따라온다. 접속 중인 사람들의 화면이 평소 경로로 갱신된다. 복원 자체가 기록에 남아 다시 되돌릴 수 있다. 복원 중에 누가 타이핑하고 있어도 변환 규칙이 그대로 처리한다.

복원 묶음은 블록 ID 기준으로 두 문서를 비교해 만든다. 과거에만 있는 블록은 다시 넣고, 지금만 있는 블록은 삭제하고, 둘 다 있는데 내용이 다른 블록은 글자 차이를 텍스트 연산으로 만든다. 64KB를 넘으면 여러 묶음으로 나눈다.

## 10.2 댓글 위치

댓글이 달린 글자에 `comment: [스레드 ID]` 서식을 붙인다. 댓글 위치를 따로 저장하지 않는다.

- 글자가 앞뒤로 밀리거나 블록이 나뉘고 합쳐져도 서식은 글자를 따라간다. 변환 규칙을 하나도 더 만들지 않는다.
- 한 글자에 댓글이 여러 개 겹칠 수 있어 값은 목록이다. 댓글 서식만은 "나중 값이 남음"이 아니라 "목록에 추가", "목록에서 제거"로 합친다. 두 사람이 같은 글자에 동시에 댓글을 달아도 둘 다 남는다.
- 댓글이 달린 글자가 전부 지워지면 서버가 적용 결과에서 이를 감지해 스레드를 `orphaned` 로 표시한다. 패널에는 당시 원문(`quote`)과 함께 "원문이 삭제됨"으로 남는다.
- 댓글 본문과 답글은 REST로 저장하고, 저장되면 문서 세션이 `comment` 메시지로 접속자에게 알린다.

댓글을 다는 순서는 스레드 생성(REST)이 먼저고 서식 연산(WebSocket)이 나중이다. 서식 연산이 실패하면 위치 없는 스레드가 남는데, 10분 안에 서식이 붙지 않은 스레드는 배치가 지운다.

## 10.3 멘션과 알림

| 단계 | 동작 |
| --- | --- |
| 입력 | `@` 를 치면 페이지에 접근할 수 있는 사람 목록이 뜨고, 고르면 글자 하나와 `mention: { id, userId }` 서식이 들어간다. `id` 는 클라이언트가 만든다 |
| 감지 | 세션이 묶음을 커밋한 뒤, 삽입 조각 중 `mention` 서식이 있는 것을 모아 이벤트로 낸다 |
| 저장 | `notifications` 에 `dedupe_key = mention:{id}` 로 넣는다. 되돌리기 후 다시 실행이나 복원으로 같은 멘션이 다시 들어와도 알림은 한 번만 간다 |
| 전달 | `user:{userId}:notify` 채널로 알리고, 그 사용자의 알림 연결(SSE)을 가진 노드가 내려보낸다 |

알림 종류는 본문 멘션, 댓글 멘션, 내 댓글에 달린 답글, 페이지 초대 네 가지다. 이메일 발송은 범위에 넣지 않는다.

## 10.4 페이지 제목과 사이드바 동기화

제목은 루트 블록의 텍스트라서 본문과 같은 방식으로 동시 편집된다. 세션은 루트 블록이 바뀐 뒤 1초 동안 추가 변경이 없으면 `pages.title` 을 갱신하고 `ws:{workspaceId}:tree` 채널에 알린다. 사이드바는 이 채널을 SSE로 받아 트리를 고친다.

## 10.5 검색

- 세션은 문서가 바뀐 뒤 5초 동안 조용하면 본문을 일반 텍스트로 펼쳐 `page_search` 를 갱신한다.
- 인덱스는 pg_bigm의 2글자 단위 GIN 인덱스다. "회의" 같은 두 글자 한글 검색어를 `LIKE '%회의%'` 로 찾으면서 인덱스를 탄다.
- 결과는 워크스페이스로 먼저 좁히고, 제한된 페이지는 9.4의 권한 계산을 통과한 것만 남긴다. 권한 없는 페이지는 제목도 노출하지 않는다.
- 정렬은 제목 일치를 본문 일치보다 위에, 그 안에서는 최근 수정 순이다.

pg_bigm은 PostgreSQL 기본 이미지에 없어서 확장을 빌드한 Docker 이미지를 따로 만든다. PostgreSQL 17에서 빌드되는지는 착수 첫 주에 확인하고, 안 되면 pg_trgm(3글자 단위)으로 시작한다.
